## 우선순위 이슈

### [P0] box-shadow 레이어 삭제가 동작하지 않는다
URL 복원 블록이 삭제 클릭 핸들러 안으로 들어갔다(패치 앵커가 파일 첫 render()에 매칭).
splice 직후 아직 갱신 안 된 주소를 다시 읽어 삭제 이전 상태로 되돌린다.
레이어 3개에서 삭제 → 3개 그대로. 기본 2레이어(주소에 l 없음)일 때만 우연히 동작.
실행취소만 켜져서 "뭔가 됐는데 화면이 안 따라온다"고 오해하게 만든다.
수정: 12줄을 클릭 핸들러 밖, 파일 끝 render() 위로.

### [P1] box-shadow 공유 링크가 원본 주소까지 지운다
같은 원인. 공유 링크 접속 → 기본값 표시 + syncUrl이 "기본값과 같으니 비운다"고 판단해 파라미터 삭제.
replaceState라 뒤로가기 복구 불가. 사용자 데이터 소실 경로.
바로 아래에 "그 주소를 공유하면 같은 그림자로 열립니다"라고 적혀 있다.

### [P1] aria-invalid="" — 무효 필드 표시가 완전히 죽어 있다
5곳에서 toggleAttribute('aria-invalid', 조건) 사용. 이는 값을 빈 문자열로 설정한다.
ARIA는 빈 값을 false로 읽고 CSS [aria-invalid='true']도 매칭 안 됨. 빨간 테두리가 한 번도 안 뜬다.
clamp는 필드 5개인데 시각 단서 0개. 오류 문구가 grid-column:1/-1로 5번째 필드 밑에 붙어 엉뚱한 필드를 지목.
수정: setAttribute('aria-invalid', String(조건)) 또는 false일 때 removeAttribute.

### [P1] 모바일 탭 순서가 화면 순서와 반대 (데스크톱 수정의 반작용)
global.css의 ≤900px 블록이 grid-row로 시각 순서만 뒤집음. DOM은 aside가 먼저 그대로.
390px 실측: 본문 첫 요소까지 / 와 /tools 13탭, /blog 20탭.
CSS 주석("링크 더미를 먼저 읽히게 두지 않고")이 사실과 다름 — grid-row는 읽는 순서를 바꾸지 않는다.
수정: DOM을 main→aside로 되돌리고 데스크톱 좌측 배치는 grid-column/areas로만.

### [P2] 사이드바가 페이지마다 정체를 바꾸고 홈에서는 빈 기둥
/tools 사이드바에 도구가 하나도 없다. 도구 상세에서 "도구" 머리글로 오면 목록이 사라진다.
홈: 사이드바 270px, 본문 1359px → 좌측 1089px 빈 여백. Persuade 화면 좌상단을 글 수 1-2개 카테고리가 차지.
