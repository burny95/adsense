## 각도를 넣었는데 방향이 예상과 다르다

`linear-gradient(90deg, red, blue)`를 썼는데 색이 좌우로
바뀝니다. 각도를 0으로 바꾸면 아래에서 위로 올라갑니다. 시계처럼 12시가
0도인 것 같기도 하고 아닌 것 같기도 합니다.

그라디언트는 값 몇 개만 넣으면 되는 것처럼 보이지만 **각도의 기준과 정지점의
규칙**을 모르면 매번 숫자를 바꿔가며 맞춰보게 됩니다. 이 두 가지만 잡으면
원하는 모양을 한 번에 만들 수 있습니다. 뒤쪽에서는 이 규칙으로 이미지 없이 만들 수 있는
것들(줄무늬, 그라디언트 테두리, 사진 위 글자, 글자 그라디언트)과 흔한 실수를 다룹니다.

## 그라디언트는 색이 아니라 이미지다

그라디언트는 CSS에서 **색이 아니라 이미지로
취급됩니다.**

```css
/* ✗ 동작하지 않는다 — color 속성은 색만 받는다 */
color: linear-gradient(90deg, red, blue);

/* ✓ background는 이미지를 받는다 */
background: linear-gradient(90deg, red, blue);
```

그래서 `background-image`, `border-image`, `mask-image`처럼 이미지를 받는
자리에는 들어가지만 `color`나 `border-color`에는 쓸 수 없습니다.

이미지라는 사실에서 따라오는 성질이 하나 더 있습니다. **크기가 요소에 맞춰
늘어납니다.** `background-size`로 크기를 정할 수 있고 지정하지 않으면 요소를
가득 채웁니다. 이 성질이 나중에 줄무늬 패턴을 만들 때 쓰입니다.

## linear-gradient — 각도의 기준

각도는 **그라디언트가 끝나는 방향**을 가리킵니다. 그리고 **0도가 위쪽**이며
**시계 방향**으로 돕니다.

| 각도 | 방향 | 같은 표현 |
|---|---|---|
| `0deg` | 아래 → 위 | `to top` |
| `90deg` | 왼쪽 → 오른쪽 | `to right` |
| `180deg` | 위 → 아래 | `to bottom` |
| `270deg` | 오른쪽 → 왼쪽 | `to left` |

두 가지가 헷갈리기 쉽습니다.

**기본값이 `180deg`입니다.** 각도를 생략하면 위에서 아래로 흐릅니다.
수학에서 각도를 다룰 때와 시작점이 다르므로, 삼각함수를 떠올리면 오히려
틀립니다.

**각도는 도착점을 가리킵니다.** `0deg`는 "위에서
끝남"입니다. "위에서 시작"으로 읽기 쉽지만 반대입니다. 그래서 첫 번째 색이 아래쪽, 마지막 색이 위쪽에 놓입니다.

방향만 필요하다면 `to top`, `to bottom right` 같은 키워드가 읽기 쉽습니다.
다만 키워드는 여덟 방향뿐이라, 그 사이 각도가 필요하면 `deg`를 씁니다.

## 색 정지점 — 위치를 적을 때와 비울 때

정지점은 **색과 위치의 쌍**입니다. 위치는 백분율이나 길이로 적습니다.

```css
linear-gradient(90deg, red 0%, yellow 50%, blue 100%)
```

위치를 비우면 브라우저가 규칙에 따라 채웁니다.

- 첫 정지점은 0%, 마지막은 100%
- 중간 정지점들은 그 사이에 **고르게** 나뉩니다

```css
/* 아래 둘은 완전히 같다 */
linear-gradient(90deg, red, yellow, blue)
linear-gradient(90deg, red 0%, yellow 50%, blue 100%)
```

정지점이 넷이면 0%, 33.3%, 66.7%, 100%가 됩니다. 그래서 **색을 고르게 배치할
거라면 위치를 아예 쓰지 않는 편이 낫습니다.** 나중에 색을 하나 추가해도
간격이 알아서 다시 나뉩니다.

### 같은 위치에 두 정지점을 두면

이건 알아두면 쓸모가 많습니다. 두 정지점의 위치를 같게 주면 그 지점에서
**색이 섞이지 않고 딱 잘립니다.**

```css
/* 왼쪽 절반은 빨강, 오른쪽 절반은 파랑 — 경계가 선명하다 */
linear-gradient(90deg, red 50%, blue 50%)
```

이 성질로 줄무늬, 눈금, 진행
막대 같은 것을 이미지 없이 만들 수 있습니다.

### 위치가 거꾸로 적히면

앞 정지점보다 작은 값을 적으면 무시되지 않고 **앞 값으로 올려서** 처리됩니다.

```css
linear-gradient(90deg, red 60%, blue 30%)
/* blue의 30%는 60%로 취급된다 → 60%에서 딱 잘린 경계가 된다 */
```

의도한 게 아니라면 값을 잘못 적은 것이니, 결과가 이상하면 정지점 순서를
먼저 확인하세요.

## radial-gradient — 가운데에서 퍼진다

`radial`에는 **각도가 없습니다.** 가운데에서 바깥으로 퍼지는 모양이라 방향이라는
개념이 없기 때문입니다. 대신 모양·크기·중심을 정합니다.

```css
radial-gradient(circle at center, white, black)
radial-gradient(ellipse at top left, white, black)
```

- **모양** — `circle`(정원) 또는 `ellipse`(타원). 기본은 `ellipse`라 요소가 가로로 길면 그라디언트도 늘어납니다
- **중심** — `at` 뒤에 위치. 기본은 `center`
- **크기** — `closest-side`, `farthest-corner` 등. 기본은 `farthest-corner`로, 가장 먼 모서리에서 마지막 색에 도달합니다

정원으로 보이길 원한다면 `circle`을 명시해야 합니다. 기본값인 `ellipse`는
요소 비율을 따라가서, 가로로 긴 카드에서는 옆으로 늘어난 타원이 됩니다.

## conic-gradient — 원을 따라 돈다

`conic`은 색이 **중심을 기준으로 각도를 따라** 바뀝니다. 원뿔을 위에서 내려다본
모양이라 이름이 그렇습니다.

```css
conic-gradient(from 0deg, red, yellow, green, red)
```

- **시작 각도** — `from` 뒤에 적습니다. 기본은 12시 방향
- **정지점 위치** — 백분율 대신 각도(`deg`)로도 적을 수 있습니다

파이 차트가 이것으로 만들어집니다. 같은 위치에 정지점을 두 개 두는 기법을
합치면 경계가 뚜렷한 조각이 나옵니다.

```css
/* 40% / 35% / 25% 파이 차트 */
background: conic-gradient(
  #b4480a 0deg 144deg,
  #f5b301 144deg 270deg,
  #1a7f37 270deg 360deg
);
border-radius: 50%;
```

정지점 하나에 시작·끝 각도를 함께 적는 축약형입니다. 색상환을 만들 때도
같은 방식을 씁니다.

## 두 색 사이가 탁해지는 이유

그라디언트를 만들었는데 중간에 회색빛 띠가 생긴 경험이 있을 것입니다. 파랑에서
노랑으로 가는 그라디언트가 특히 그렇습니다.

브라우저가 두 색 사이를 채우는 방식은 단순합니다. **양쪽 색의 R·G·B 값을 각각
직선으로 이어서** 중간값을 계산합니다.

```
파랑 rgb(0, 0, 255)  →  노랑 rgb(255, 255, 0)

중간 지점: R=(0+255)/2=128, G=(0+255)/2=128, B=(255+0)/2=128
        → rgb(128, 128, 128) — 회색
```

**중간이 정확히 회색이 됩니다.** 두 색을 잇는 직선이 하필 무채색 지점을
지나가기 때문입니다. 보색에 가까운 색끼리 이을수록 이 현상이 뚜렷합니다.

**중간에 정지점을 하나 더 넣어** 해결합니다. 채도가 살아 있는 중간색을
직접 골라 넣으면 회색 지대를 피해 갑니다.

```css
/* ✗ 중간이 회색 */
linear-gradient(90deg, #0000ff, #ffff00)

/* ✓ 중간에 초록을 거쳐 간다 */
linear-gradient(90deg, #0000ff, #00b3a4 50%, #ffff00)
```

어떤 색을 넣을지는 두 색을 HSL로 바꿔 색상(H) 값을
확인하고 그 중간 각도의 색을 골라 보면 감이 잡힙니다.

`transparent`로 사라지게 만들 때는 사정이 조금 다릅니다. `transparent`는 사실
**투명한 검정**(`rgba(0, 0, 0, 0)`)입니다. 예전 브라우저는 이 검정을 그대로 섞어서
흰색에서 `transparent`로 갈 때 중간이 회색으로 떴습니다. 지금은 브라우저가 알파를
미리 곱해서 계산하기 때문에 이 현상은 나타나지 않습니다. 널리 인용되는 이야기지만
이제는 옛말입니다.

그래도 같은 색의 투명한 버전(`rgb(255 255 255 / 0)`)으로 끝내는 편이 낫습니다.
어떤 색에서 사라지는지가 코드에 그대로 드러나기 때문입니다.

## 그라디언트가 이미지를 대신할 수 있는 곳

앞에서 본 것처럼 그라디언트는 CSS가 그리는 이미지입니다. 그래서 **파일을 하나도 요청하지 않고**
배경 무늬를 만들 수 있습니다. 요소 크기에 맞춰 늘어나고 확대해도 깨지지
않으며 색을 CSS 변수로 바꿀 수 있습니다.

- **잘 맞는 곳** — 줄무늬·격자 같은 규칙적인 무늬, 테두리 장식, 사진 위에 얹는
  어두운 막, 구분선, 스켈레톤 로딩의 반짝임
- **안 맞는 곳** — 불규칙한 질감, 사진, 로고. 정지점을 수십 개 쌓아 그림을
  그리는 것보다 SVG나 이미지 파일이 낫습니다

저도 처음에는 배경을 이미지로 만들어 넣었습니다. 배경 디자인이 확정되기 전에
화면부터 만들어야 했는데, 수정이 오갈 때마다 이미지를 다시 만들어 교체해야
했습니다. 그걸 본 사수가 이미지로 하지 말고 그라디언트 생성기로 배경을 만들어
넣어 두라고 했고 그 뒤로는 그렇게 넣어 둡니다. 아직 바뀔 여지가 많은 배경일수록
파일보다 CSS 값으로 두는 편이 고치기 쉽습니다.

## 실전 1: 줄무늬와 패턴

앞에서 다룬 "같은 위치에 정지점 두 개" 규칙을 반복하면 줄무늬가 됩니다.
`repeating-linear-gradient`는 그 반복을 대신해 줍니다.

```css
/* 12px 주황, 12px 노랑이 45도로 반복 */
.stripes {
  background: repeating-linear-gradient(
    45deg,
    #b4480a 0 12px,
    #f5b301 12px 24px
  );
}
```

정지점 하나에 시작·끝 위치를 함께 적는 축약형(`#b4480a 0 12px`)을 쓰면 같은
색을 두 번 적지 않아도 됩니다.

주의할 점은 **정지점 위치가 그라디언트 선을 따라 잰 거리**라는 것입니다. 45도로
기울여도 줄 두께(줄과 직각으로 잰 거리)는 12px 그대로지만 **가로로 재면 약
17px**(12 ÷ cos45°) 간격이 됩니다. 세로줄과 같은 값을 넣었는데 기울인 쪽이
성기게 보이는 건 이 때문입니다. 가로 간격을 맞추고 싶다면 각도에 맞춰 값을
줄여야 합니다.

## 실전 2: 그라디언트 테두리

`border-color`는 그라디언트를 받지 못합니다. 대신 배경을 두 겹으로 깔고
**각 겹이 차지하는 영역을 다르게** 지정하면 테두리만 그라디언트가 됩니다.

```css
.gradient-border {
  border: 3px solid transparent;
  border-radius: 12px;
  background:
    linear-gradient(#fff, #fff) padding-box,      /* 안쪽 면 */
    linear-gradient(90deg, #b4480a, #1a7f37) border-box; /* 테두리까지 */
}
```

첫 번째 겹은 `padding-box`라 테두리 안쪽까지만 그려지고 두 번째 겹은
`border-box`라 테두리 영역까지 그려집니다. 테두리를 `transparent`로 비워 뒀기
때문에 그 자리로 아래 겹이 비쳐 보입니다. `border-radius`도 그대로 따라옵니다.

**한계가 하나 있습니다.** 안쪽 면을 불투명한 색으로 덮는 방식이라, 배경이
사진이거나 투명해야 하는 곳에서는 쓸 수 없습니다. 그런 경우에는 안쪽 색을
부모 배경색과 같게 맞추거나, `mask`를 쓰는 다른 방법이 필요합니다.

## 실전 3: 사진 위 글자를 읽히게 하기

사진 위에 흰 글자를 얹으면 밝은 부분에서 글자가 사라집니다. 사진 전체를
어둡게 하면 사진이 죽습니다. **글자가 있는 쪽만 어둡게** 하면 됩니다.

```css
.photo-caption::before {
  content: '';
  position: absolute;
  inset: 0;
  /* 위쪽 40%는 손대지 않고, 아래로 갈수록 어두워진다 */
  background: linear-gradient(transparent 40%, rgb(0 0 0 / 0.75));
}
```

사진은 위쪽이 그대로 보이고 글자가 놓인 아래쪽만 어두워집니다. 어두운 정도는
`0.75` 부분으로 조절하는데, **흰 글자 기준 대비 4.5:1을 넘기는 값**인지
확인해 두면 안전합니다([색 대비 글](/blog/wcag-contrast-basics/)에 계산법을 정리해 뒀습니다). 사진마다
밝기가 다르므로 가장 밝은 사진을 기준으로 잡습니다.

이 문제는 메인 슬라이드에서 실제로 겪었습니다. 사진이 깔린 메인 슬라이드 위에
글자를 흰색으로 넣어 달라는 요청이었는데, 배경 사진이 밝은 장에서는 글자가
묻혀 잘 보이지 않았습니다. 슬라이드처럼 사진이 계속 바뀌는 자리는 어두운 사진
한 장만 보고 판단하면 안 됩니다.

## 실전 4: 글자에 그라디언트

배경을 글자 모양으로 오려내고 글자색을 투명하게 만듭니다.

```css
.gradient-text {
  background: linear-gradient(90deg, #b4480a, #f5b301);
  -webkit-background-clip: text; /* 접두사만 아는 옛 브라우저용 */
  background-clip: text;
  color: transparent;
}
```

글자 자체는 그대로 남아 있어서 선택·복사·검색·낭독이 모두 됩니다. 이미지로
만든 제목과 다른 점입니다.

다만 **`color: transparent`가 위험한 조합**이라는 것은 알고 써야 합니다.
배경이 어떤 이유로든 그려지지 않으면 글자가 통째로 사라집니다. 고대비 모드처럼 색을 강제로 바꾸는 환경
(`forced-colors`)도 따로 챙겨 두는 편이 안전합니다. 큰 제목 한두 개에만 쓰고 본문이나
버튼 라벨에는 쓰지 마세요.

```css
/* 고대비 모드에서는 평범한 글자로 되돌린다 */
@media (forced-colors: active) {
  .gradient-text {
    background: none;
    color: CanvasText;
  }
}
```


## 흔한 실수

- **그라디언트에 `transition`을 걸어 두고 부드럽게 바뀌길 기대하는 것** —
  걸리지 않습니다. 2초짜리 전환을 걸고 0.7초 시점에 값을 읽어 보면 이미 최종
  그라디언트로 바뀌어 있습니다. 같은 시점에 `background-color`는 아직 중간에
  있는 것과 대조됩니다. 부드럽게 바꾸려면 **두 겹을 겹쳐 놓고 위 겹의
  `opacity`를 전환**하세요. 그라디언트에 쓰는 색을 `@property`로 등록한 CSS 변수로
  만들면 그 변수는 전환할 수 있지만 지원하는 브라우저 버전을 확인하고 써야 합니다.
- **넓은 면적에 아주 완만한 그라디언트** — 색은 채널당 256단계뿐이라, 색 차이가
  작을수록 계단(밴딩)이 눈에 띕니다. 면적을 줄이거나 두 색의 차이를 키우면
  덜합니다.
- **`transparent`로 끝내면 회색이 낀다고 믿는 것** — 예전 브라우저 이야기입니다.
  지금은 나타나지 않습니다. 자세한 이유는 앞의 "두 색 사이가 탁해지는 이유"에
  적어 뒀습니다.
- **`background`를 통째로 덮어쓰는 것** — 그라디언트를 `background` 단축 속성에
  적으면 `background-color`까지 초기화됩니다. 그라디언트가 로드되기 전이나
  지원하지 않는 환경에서 배경이 비어 보일 수 있으니, 대체 색을 먼저 적고
  그라디언트를 뒤에 적으세요.
- **정지점을 색상환 반대편끼리 잇는 것** — 중간이 무채색을 지나며 탁해집니다.
  두 색을 HSL로 바꿔 `H` 값을 확인하고 차이가 크면
  중간 정지점을 하나 넣습니다.

## 요약

- 그라디언트는 **이미지**다. `background`에는 되지만 `color`에는 안 된다. 파일 요청 없이 그려져 규칙적인 무늬·테두리·막에 쓴다
- `linear`의 각도는 **0도가 위, 시계 방향**이고 **도착 방향**을 가리킨다. 기본값은 `180deg`
- 정지점 위치를 비우면 브라우저가 고르게 나눈다. 고르게 둘 거면 아예 쓰지 않는 게 낫다
- **두 정지점을 같은 위치에 두면 경계가 딱 잘린다.** 줄무늬·차트의 원리
- `radial`에는 각도가 없다. 정원을 원하면 `circle`을 명시해야 한다
- `conic`은 정지점을 각도로 적을 수 있다. 파이 차트가 여기서 나온다
- 중간이 탁해지는 것은 **RGB를 직선으로 잇기 때문**이다. 중간 정지점을 넣어 피한다
- 줄무늬는 `repeating-linear-gradient` + 정지점 축약형(`색 0 12px`). 기울여도 줄 두께는 그대로고 가로 간격만 넓어진다
- 그라디언트 테두리는 `padding-box`/`border-box` 두 겹. 단, 안쪽이 불투명해야 한다
- 사진 위 글자는 **글자 쪽만 어둡게** 하고 가장 밝은 사진 기준으로 대비를 확인한다
- 글자 그라디언트는 글자가 그대로 남아 좋지만 `color: transparent`라 고대비 모드 대비가 필요하다
- **그라디언트에는 `transition`이 걸리지 않는다.** 두 겹을 겹치고 `opacity`를 전환한다
